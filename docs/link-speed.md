# 手动公网线路测速（MVP）

本功能位于独立 Glivela 控制面板，不使用 Vastora 的旧私网测速接口。

## 使用与结果

在「线路组合」选择线路，在对应落地的详情中勾选公网直连、公网 SS2022 或两者，点击「开始测速」。列表按入口和落地配对显示最近结果，多个账户共用同一配对时展示相同测量。已知参考延迟超过100ms的配对排除；离线、临时停用、配额策略停用不自动恢复。

客户端链式组合也可测速，不要求另建服务端转发组合。控制端从启用且账户凭据有效的链式组合生成独立 `speedPeers` 策略，以配置修订绑定入口身份；落地仍按实际已应用的链式监听和精确来源核验。IPv4 和 IPv6 使用各自登记的公网传输地址，不跨地址族回退。修改或撤销组合、凭据、身份、来源或配置后，未完成任务仍按现有规则停止并清理。

控制端和两端节点须统一支持 `link-speed.v7`。该升级会投影测速授权策略并更新相关入口的配置修订，不创建转发授权、Xray 路由或新业务凭据。测试仍使用隔离的临时监听和一次性认证，结果表示入口到落地的点对点传输能力，不代表用户客户端整条代理链路的速度。

两种结果并列显示，各含线路→落地和落地→线路接收速率。一次任务只显示本轮所选方式，未选择的格子为空；失败明确显示原因，不显示0，不拿其他任务或其他方式的数据填充。未收到清理确认不算成功。一次只允许一个任务，节点端串行执行，控制和正常健康上报不等待传输。

测速使用 Glivela 原生节点包内固定的 iperf3 3.22，线路端和落地端均须更新到包含该工具的版本。发布构建按架构核对固定 SHA256、第三方构建仓库和 GitHub 构建证明；节点只执行同一受签名目录保护的安装包内文件，使用前核对版本、认证支持和摘要，不回退系统程序。缺失或校验失败仅令测速不可用，不改变现有代理。

第三方静态包包含 musl 与 OpenSSL；其上游构建使用未固定摘要的构建输入，构建证明不能证明全部输入可复现或没有漏洞。需要跟踪 iperf3、OpenSSL 与 musl 的安全更新，并通过新的 Glivela 版本更换固定文件；系统包更新不会更新静态依赖。随发行包提供第三方许可证。

## 测试边界

- 测量数据直接在两台服务器之间传输，管理端和控制通信不承载测速负载。
- 公网直连使用临时 TCP35260（上传）、35262（下载）；SS2022 使用临时 TCP35261（上传）、35263（下载），固定2022-blake3-aes-128-gcm，不开启UDP、多路复用或备用出口。不同端口不能单独用于推断端口QoS或协议开销。
- SS2022是同一对已授权节点间的**隔离临时协议测试**，使用一次性测试密钥及临时Xray进程，不修改或经过正式1080监听。临时服务只能转发至本机iperf接收端，不能成为通用代理。不代表原订阅或正式SS2022业务已验收。
- 直连上传、直连下载、加密上传、加密下载分别执行；每项单 TCP 连接，预热 1 秒后正式测量 8 秒。当前不设置字节流量上限；时间、内存及任务租约限制仍有效。预热、协议开销和重传都会消耗流量，页面显示实际已用流量，不代替供应商账单或原业务账本。一项失败不会阻止其他已选择的项执行，失败项保留真实原因。
- 预热不计入正式速度样本；收尾、计时窗口及路径波动仍会影响结果，不代表链路最高容量。后端按 iperf3 实际接收量和时间保留 Mbps，界面除以 8 显示 MB/s，并保留方向、平均速度、峰值和逐秒样本。分别保留发送、接收字节，结束时在途数据可能尚未计入接收值。SS2022 的 iperf 重传为内层 TCP，不能当作公网外层丢包率。
- 支持已授权的公网 IPv4 或 IPv6 SS2022 配对。IPv6 使用已登记的精确源/目标地址，不自动选择或回退地址族；不接受任意目标或任意端口输入。管理仍使用现有 mTLS 私网控制通道。

## 临时执行与清理

控制端仅对明确登记、业务启用、运行回执有效且已连接 Glivela gRPC 测速通道的节点下发任务。任务绑定两端身份、修订与配置摘要，接收端和发送端只能取得各自阶段的任务；回执重试幂等，不重复传输。模式、结果、任务时间和清理状态来自同一任务。

节点私有目录保存临时认证、一次性密钥和资源归属记录。独立nft表只约束测试端口，精确来源放行；当前没有字节流量配额，租约和资源保护仍有效。已知的独立主机guard可以添加带任务归属标记、来源集合且4分钟自动过期的临时例外；其他未知默认拒绝策略报错，不能自动放宽。正式Glivela防火墙、DNS、Xray配置、身份、订阅和账本均不重写。

任务总租约4分钟；进程在截止、父进程退出或内存保护触发后结束。可用内存低于128MiB或临时磁盘少于32MiB时拒绝开始，运行期间低于64MiB停止。正常结束删除本任务进程、规则、集合及文件；崩溃重启只恢复清理自己私有归属记录中的测速资源。清理未确认明确失败，不伪造已完成。

控制端私有 `speed-tasks.json` 保留最近32组任务的元数据、已认证Glivela管理证书的提交者指纹、进度和结果，排除临时密码、PSK和认证私钥。节点 `control-speed-receipts.json` 保留最多128条阶段回执，在执行前持久化任务身份，终态收到主控确认后标记已确认。传输断线不停止执行；重连补发同一回执，主控确认后才移出重发队列，不重新跑测速。已下发阶段重连时不会仅因心跳过期取消，但仍检查租约、节点身份、配置、额度、凭据和手动停用。

节点进程重启先清理本机已归属临时资源，未结束的阶段明确失败；控制端进程重启将未结束任务转入两端清理，不从缺失临时密钥的状态重新执行。已完成结果仍可查询。终态与清理是否确认分别展示，不能把重连、发送成功或清理请求当成测速成功。

## 接口与协议

管理端沿用 Glivela 管理员mTLS、同源JSON POST：

- `POST /v1/admin/link-speeds`，`{}`读取当前 `revision`（十进制字符串）和 `tests`，以及各已登记节点的控制通道连接状态。连接状态的无任务刷新随15秒有界等待返回，不将历史心跳等同于当前连接。
- `start` 对象包含随机UUID `id`、`entryId`、`landingId`和 `modes: ["direct", "ss2022"]`，不接收地址、端口、命令或路径。
- `{ "afterRevision": "123" }` 等待该版本变化，最多15秒；变更立即唤醒。面板离开线路组合页时取消，隐藏标签暂停；重连保留结果，旧响应不覆盖新版本。

节点只用 HTTP/2 gRPC `glivela.control.v1.NodeControl/Connect` 下发测速和回传进度/结果；旧节点 `POST /v1/link-speeds` 已删除，没有双通道兜底。执行前使用同一节点 mTLS 身份只读查询当前配置，不上报空健康回执；策略待更新时拒绝执行。配置、延迟和 BBR/FQ 等具名节点操作沿用同一受认证 gRPC 通道；管理网页与订阅继续使用各自现有 HTTP 接口。BBR/FQ 归属仍是 Glivela。

每个已登记证书只保留一个当前会话，新会话替换旧会话；每次状态变更再次检查证书与会话，身份撤销唤醒连接并拒绝后续任务/回执。Hello和发送有10秒限时，消息64KiB、收取队列有界，重连退避1–30秒。连接建立使用相同Glivela CA/客户端证书与服务器名称校验；不接受Vastora会话或未知节点冒充。临时测速认证只发送给既有阶段接收者，不进入浏览器、普通日志或上述元数据文件。

每个阶段分别记录主控收到“接收/开始”消息的时间、节点报告完成时间、主控持久化确认时间；这些不是同步时钟下的单向网络延迟。节点回执丢失可重发，幂等依据任务ID、阶段和参数摘要，不能换参数重用同一任务。

协议生成方式见 [proto/README.md](../proto/README.md)。源码、验证、发布和上线验收分别记录到对应主 issue。

## Host firewall boundary

For an independently managed default-drop host input policy, temporary receiver
exceptions support only the generic `inet host_guard` table and its `input` chain.
They remain bound to the exact authorized source, speed-test ports and expiry.
Other drop-policy tables require explicit operator preparation; Glivela does not
rewrite them. This source baseline does not rename any installed host firewall.
