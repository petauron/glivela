# 节点网络优化

入口：Glivela 独立管理页 → 节点状态 → 网络优化列。使用现有管理员证书；
不是 Vastora 通用远程命令入口。控制端与原生节点端都需要包含此功能的版本。

## 使用

1. 点击节点的 BBR/FQ 状态，查看内核、出口网卡、实际及默认队列、TCP 缓冲值和检测时间。
   绿点表示已测得开启，黄点表示未开启，红点表示操作失败，灰点表示未确认、过期或处理中。
   每个状态同时有文字；不能用默认队列代替实际网卡队列，也不代表吞吐一定改善。
2. 一键优化只依据节点实测内存计算收发缓冲最大值：每满或不足 64 MiB 内存建议 1 MiB，
   最小建议 4 MiB，并受 `min(主机内存 / 32, 256 MiB)` 约束。内存不足或缺失时不能应用。
   例如约 512 MiB 内存建议 8 MiB，约 1 GiB 建议 16 MiB。线路带宽、RTT 和地理位置不参与计算。
3. 应用只提高收发最大值及对应 socket 上限，保留更高现值、最小值、默认值、窗口缩放和接收自调。
   缓冲上限并非预分配或总内存保证；高并发仍须观察内存。请求排队不等于应用成功，以节点读回结果为准。
4. “恢复应用前配置”恢复第一次受管应用前的快照，并移除自有持久配置。
   后续外部改动、复杂队列或出口变化时拒绝覆盖，需人工核对；超时不代表撤销。
   应用中断会保留备份并阻止再次自动应用，重新检测后显式恢复。

## 范围与持久化

- 仅原生 Linux、root 节点进程与 PID 1 相同网络命名空间、单一默认出口，且已有 `ip`、`tc`。
  不安装工具、内核或加载模块；内核尚未提供 BBR 时显示原因。
- 复用管理员/节点 mTLS 身份及证书绑定；只提供检测、应用固定参数、恢复三个受限动作，
  不接受任意命令、路径或探测地址。操作包含修订号、当前状态指纹、过期时间和管理员证书标识。
- 生效范围是主机网络命名空间内所有 TCP 服务，不仅所选代理线路。
  已有连接可能继续使用旧拥塞算法；替换简单根队列可能短暂影响流量。
- 只替换默认 `pfifo_fast`/默认 `fq_codel`；已有 `fq` 不重建。多队列、复杂整形或未知配置拒绝应用。
  不修改路由、IPv6、MTU、防火墙、conntrack、代理账户或订阅。
- 原始快照与操作结果保存在节点私有状态目录的 `network-optimization.json`（0600）。
  持久参数为 `/etc/sysctl.d/90-glivela-network.conf`，只覆盖核对归属的文件。
  系统重启后由 sysctl.d 恢复参数，节点启动仅在值/出口仍匹配且没有自定义整形时恢复简单 FQ。
  普通进程重启不重设队列。不匹配时保持现状，页面显示实际值。
- 节点每分钟读取一次内核；命令通过独立串行循环接收，结果失败不触发无限重试。
  控制端不把周期快照落盘；旧带宽、RTT 和路径设置保留在既有记录中但不再参与计算，最新操作回执持久化。状态超过两分钟不可用于应用。
- 卸载节点应用前，如果不再需要这些系统参数，先在此面板恢复；卸载不隐式删除备份或重置主机网络。
