# 路径 MTU

入口：Glivela → 线路组合 → 选择线路 → 路径 MTU。

- 默认使用系统自动路径 MTU；打开详情会读取已授权目标的实际路由。
- 选择手动值并应用，或选择自动并恢复。IPv4 最小576，IPv6 最小1280，最大不超过出口网卡MTU。
- 设置属于“入口节点＋目标IP”。相同目标上的多账户、端口或线路共享设置；并发修改必须刷新当前修订后重试。
- 显示配置值、实际路由MTU、执行中及失败原因。提交成功不等于节点已经应用，以节点读回为准。

## 边界

只支持现有授权的公网落地传输目标；浏览器不能传入任意IP、网卡、网关、路由表或命令。
不改网卡全局MTU、默认路由、DNS、出口、代理配置/进程、订阅、身份、账户或账本。
同一目标IP的其他连接也使用此主机路由，不能将它描述成仅某个端口或账户独享。

复用 Glivela 的管理员认证、节点 mTLS/gRPC 通道和网络操作串行执行。
不需要修改 Vastora 安装器或新增依赖。节点需要包含此能力的版本和现有 root 网络权限。
LXC 可调整自己的网络命名空间中的目标路由；BBR/FQ 的容器限制保持不变。

## 归属、失败与恢复

节点只在主路由表创建精确 /32 或 /128 路由，保留实际下一跳、源地址和网卡，使用自有协议标识及私有归属记录。
已有非自有主机路由、复杂/等价出口、策略路由或无法核验的外部修改会被拒绝。
应用前在节点状态目录的 `path-mtu.json`（root/0600）记录恢复意图，应用后核对真实内核路由。
普通失败仅对仍匹配本次意图的自有路由恢复，不覆盖不明来源的路由；无法确认时保留记录并显示失败。
恢复自动仅移除匹配归属记录的目标路由，让原系统路由继续生效，不删除基础路由。

状态文件保留手动设置。系统重启后，节点重新取得当前授权配置，基础路径与原记录一致且目标路由不存在时重新应用。
私网身份或控制连接暂不可用时会在后续正常观测周期再核对，不重启代理、不重复覆盖现有路由。
移除线路或改变目标地址前，先恢复该目标的自动设置；本功能不清理历史目标记录，也不接管外部已有主机路由。
已有连接可能继续使用之前协商的MSS。此功能不承诺吞吐提升；应以实际访问和必要的测速判断效果。
